# Proposal-Only Evidence Maintenance

Use the unified Evidence contract, not the legacy library schema. The authoritative data stays unchanged in this version.

1. Bind the actual baseline version/hash and supplementary source materials.
2. Search existing contributions/cases/sources. Duplicate identity means the same real fact, responsibility, and scope; matching wording or project names only trigger review.
3. Show proposed additions/revisions, exact before/after differences, source support, conflicts, affected references, and unresolved questions. Distinguish factual changes from presentation changes.
4. Describe merge/split and old-reference handling as proposals. Do not allocate formal IDs, claim implemented lineage, or use legacy apply tools. Unsupported multiple-source STAR or replacement mappings require a future data-contract decision.

Fact approval and formal ID approval must refer to exact content; extraction or POC approval does not supply either. Pending facts remain pending. Existing IDs are never assigned to another experience. Sources and generated text are distinct; a polished story does not establish truth. Semantic duplicate/conflict judgments need user review.
