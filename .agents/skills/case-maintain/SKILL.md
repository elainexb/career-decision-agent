# Case Maintain

Input: one [Evidence document](../resume-intake/references/output-contract.md), actual new materials, and a maintenance request. Output: a concrete change proposal and impact list under the caller's proposal contract. This version does not apply changes.

Retrieve existing contributions first. A case adds real event context and source links to existing Evidence; it does not duplicate the stored actions/results. New context needs its own source. Refine Situation, Task, Action, Result, responsibility, metrics, and limitations only where materials support them. Keep missing details Unknown; never infer actions from an outcome.

Read [maintenance rules](../career-decision/references/library-maintenance.md). Compare the same real fact, responsibility, and scope to identify duplicates; shared project names or similar wording only trigger review. Present conflicting accounts for user resolution.

Show proposed additions/revisions, sources, before/after differences, affected references, and unresolved questions. Identify merge/split or multiple-source STAR changes that the current schema cannot represent. Extraction permission is not approval of facts or IDs. Keep the authoritative Evidence unchanged and make no claim of an applied update.

Use the shared [proposal contract](../evidence-maintain/schemas/proposal.schema.json) for harness runs.
