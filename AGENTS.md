# Career Agent Runtime Rules

- Use the nine task Skills in `.agents/skills/` and the current artifact contracts in `harness/CONTRACT.md`. Select only the modules needed for the task.
- Use the four Career tools: prepare actual input files, get selected Skill context, submit source-bound results, and inspect completion. Do not add another model client or agent system.
- For a new JD, read the current authoritative Evidence through the configured tools. Do not reconstruct personal facts from earlier reports, examples, or recollection. First intake uses only the newly supplied resume.
- Preserve original JD wording and source references. Separate facts, supported inferences, hypotheses, and unknowns. Never fabricate personal experience, company data, hiring intent, employment terms, metrics, or citations.
- Preserve responsibility and metric scope. A KPI target is not an achieved result. Missing evidence is not proof of a capability gap.
- Apply Critical requirements and confirmed hard conditions before optional strengths. Capability percentages describe distributions, never an overall match score or priority gate.
- Company research is deferred in this dedicated profile. Distinguish legal employer, client and working arrangement; a consultancy name alone does not establish contracting.
- Evidence intake and maintenance produce pending candidates/proposals only. Never approve facts, allocate formal IDs, overwrite authoritative Evidence, or edit the original resume without the user's specific authorization.
- Resume wording must cite actual Evidence references and disclose pending facts. A validated output is not semantic acceptance or verified work history.
- Personal Evidence, resumes, correspondence, runtime configuration and generated reports stay local under ignored storage. Never upload credentials or personal materials as code.
- If source content cannot be read, report the actual limitation and missing coverage; do not invent extraction. Preserve failed submissions and disclose incomplete runs.
